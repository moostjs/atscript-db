# Actions on a view — `@DbActionsFrom` (0.1.147)

List a source controller's row / rows actions on another readable controller (typically a `@ViewController` whose rows stand for the source's rows). The actions stay the source's. Docs: `docs/http/view-actions.md`.

## Quick start

```ts
import { AsDbReadableController, DbActionsFrom, ViewController } from "@atscript/moost-db";

@ViewController(IssueBoard)
@DbActionsFrom(() => IssueController) // id ← IssueBoard.id (derived)
@DbActionsFrom(() => LineController, {
  idMap: { issueId: "issue", lineNo: "line" },
  actions: ["close"],
})
export class IssueBoardController extends AsDbReadableController<typeof IssueBoard> {}
```

## Invariants

| #   | Rule                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                             |
| --- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 1   | The SOURCE decides everything: its guards, `prepareRequest`, `allowedActions`, row overlay, `actionRowScope`, `disabled` — evaluated "as itself" in a child of the view's event (moost `withControllerContext`: writes stay in the child, the view request's DI scope is SHARED — source `FOR_EVENT` deps resolve). Put permissions on the source.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                               |
| 2   | `idMap` = source identification field → view path. Keys must equal ONE source identification (PK or unique index). Omitted → derived: each source `preferredId` field must map to exactly one plain view column (no aggregate, no JSON leaf) — else a config error suggesting `idMap`. Non-view controllers REQUIRE `idMap`.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                     |
| 3   | Config errors (unknown / table-level action, name collision with own or another delegation's action, source not registered / not `AsDbReadableController`, bad `idMap`) throw at the first `/meta` / read that needs the delegation. `@DbActionsFrom` on a value-help controller throws at decoration.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                           |
| 4   | `/meta`: delegated entries follow the view's own (several `@DbActionsFrom` → declaration order, top decorator first), with `owner` (source base path), `idMap` (omitted when identical AND = view `preferredId`), `formUrl` → source form; NO `disabled` string. The view's `applyMetaOverlay` never sees them.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                  |
| 5   | `$actions` on view rows = the source's verdict for the mapped row (same as the source's `GET /meta/actions/:id`). `idMap` columns are always selected AND kept. A row with a null mapped value gets none. A source 401/403 → no delegated actions (not an error).                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                |
| 6   | A view `hasField` hiding — or `transformProjection` dropping — an `idMap` path drops that delegation for the request (meta, `$actions`, query targets).                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                          |
| 7   | View `GET /meta/actions/:id` / `?…` answers delegated actions only when the source id is the request id renamed (`?issueId=7`); otherwise ask the `owner`.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                       |
| 8   | Execution: the client POSTs to `value` (the source's route) with ids mapped through `idMap` — `client.action()` maps, `actionIdentifier()` for UIs.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                              |
| 9   | Query target on a delegated action whose source declares `queryTarget`: `POST {view}/delegated-actions/:name` (`queryTarget.url`; route exists ONLY on controllers declaring `@DbActionsFrom` + subclasses). Order: source `allowedActions` must list it (else 403, dryRun too) → view resolves rows under ITS read scope (`transformFilter(q) ∧ ¬exclude`, ∧ `queryTargetScope` only when overridden) → map to source ids (no id → skipped `"unmapped"`, only VISIBLE view id fields echoed; deduped; `exclude`d view rows remove their SOURCE row even if other view rows map to it) → per batch `min(batchSize, maxIds)`: re-check view rows from batch 2 on (none still matching → skipped `"stale"`), run the SOURCE route via `MoostHttp.invoke` (full pipeline). Ids refused before the handler started (the gate) skipped + batch rerun once; handler-thrown `ActionDisabledError` is NOT rerun. `dryRun` / `expectCount` count VIEW rows. Delegated action without `queryTarget` → 400 `TARGET_INVALID`; unknown → 404. |
| 10  | View `prepareRequest` sees `endpoint: "delegatedAction"`, `ctx.action` on that route; `getDbEndpoint()` reports it.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                              |
| 11  | `hasActionDelegations(ctor)` tells a permission layer a controller delegates (e.g. don't 403 its `/meta/actions` for lack of an own grant).                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                      |
| 12  | Result `TDbActionTargetSummary`: "ran" = a source handler STARTED (guards, gate, later interceptors, arg pipes incl. `@InputForm` validation all passed). Error before ANY handler started → that error as the source answers it (403 no action grant; invalid/missing `input` → the source's 400 with `errors[]` — same input every batch). Later failure → 201 partial summary with `aborted {status,message}`, failed batch + remaining ids in `failed` (a source `@DbActionTarget` handler's own partial summary is merged, then the run stops). Batch the handler never reached (interceptor replied) → `failed` `"not run"`. Source handler's string `message` → `messages[]` (per batch) + `message` (distinct, `\n`-joined).                                                                                                                                                                                                                                                                                             |
| 13  | Inside a batch the SOURCE sees: body readers (`@Body`, `@RawBody`, `useBody`, `rawBody()`, `@DbActionIDs`) = `{ ids, input }` of the batch; own route params / controller context / fresh `FOR_EVENT` scope (released per batch). BUT headers, auth, `url`, query string = the VIEW request's; `useResponse()` writes discarded; `getRawRes()` writes hit the view's socket — never authorize on url/query in a source action.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                   |
